# Рабочая 3D-комната

По просьбе владельца комната и отдельные модели разделены на этапы.
Сейчас работает процедурная основа: общий стол, 17 стульев, стены с настоящими
проёмами, шкафы, настенные заготовки и освещение. Персонажи и подробные модели
интерактивных предметов пока не добавляются.

## Где открыть

- `room3d.html` — самостоятельная WebGL-комната.
- В приложении: «Ещё → Комната клуба». HTML комнаты встроен в sandbox-iframe,
  поэтому сырой предпросмотр не требует соседнего файла или внешнего CDN.
- Видео обзора снимается с настоящей WebGL-сцены, а не с изображения макета.

Мышь и касание поворачивают камеру; колёсико/два пальца меняют масштаб.
Есть общий вид, вид сверху, изнутри и точки у стола, полок и доски.
Стрелки и +/− работают при фокусе на canvas; Home возвращает общий вид.
Escape внутри встроенной комнаты закрывает окно клуба. Сообщения от других
окон не принимаются: родитель проверяет конкретный `contentWindow` iframe.

Невидимые стены в обзорном режиме — намеренный разрез: геометрия сохраняется,
но ближайшая к внешней камере стена и потолок скрываются для обзора.
Это просмотр модели с orbit-камерой, не прогулка с физическими столкновениями.

## Сборка

```bash
python3 -B scripts/export_room3d_runtime.py room3d.html
python3 -B scripts/embed_room3d_viewer.py
python3 -B scripts/export_demo.py /tmp/dearfriends-room3d-club.html
```

Геометрия берётся из `rooms/club-room-3d/geometry-metadata.json`. Процедурный
viewer создаёт объёмы заготовок, объединяет повторяющиеся части через instancing
и делает реальные отверстия стен экструзией контуров. GLB из Blender не
экспортируется. Three.js 0.180.0 хранится локально с MIT LICENSE и происхождением
в `assets/vendor/three/provenance.json`; npm или сборщик для просмотра не нужны.
Клубные данные и Supabase в viewer не передаются.

Новые модели можно добавлять по одной к устойчивым точкам в
`rooms/club-room-3d/runtime/interactive-anchors.json`. Сейчас поле `model` пусто;
там же перечислены части заготовки, которые позднее заменит готовая модель.

## Надёжность и проверка

Рендер работает по требованию: после завершения движения камеры кадры не
рисуются непрерывно, скрытая вкладка не рендерится. На узком экране ограничены
pixel ratio и карта теней. Графическая ошибка показывает макет и объяснение;
есть повторная загрузка контекста. Проверка не обещает FPS на реальном iPhone.

```bash
PYTHONPATH=tests python3 -B -m unittest test_room3d_runtime test_navigation -v
python3 -B scripts/render_room3d_walkthrough.py room3d.html /tmp/room-tour.mp4
```

Прошли 17 проверок в локальном Chromium: WebGL с программным GPU, геометрия,
покой рендера, камера/колесо/клавиатура, мобильная раскладка, восстановление
контекста, отсутствие WebGL, сырой srcdoc, окно клуба и прежняя навигация.
В общем виде зафиксированы 6592 треугольника и 22 draw calls; это статистика
упрощённой основы, а не бюджет будущих подробных моделей.

Полный пайплайн финальных моделей, GLB/текстурных уровней и опубликованного
runtime не объявлен пройденным. Внешние сервисы генерации моделей не вызывались.
Ветка и рабочая Supabase в удалённую среду этим шагом не публиковались.

## Загрузка из основного окна

При открытии «Комнаты клуба» основной интерфейс переводит вложенный iframe
из `loading="lazy"` в `eager`. Без этого браузер мог оставить окно пустым
после переноса скрытого раздела в диалог, особенно внутри sandbox-предпросмотра.
Браузерная проверка ждёт готовый viewport через FrameLocator,
а не синхронное наличие `content_frame`.
