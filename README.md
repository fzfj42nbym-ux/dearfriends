# Dear Friends

Исходники сайта **Dear Friends** — сообщества друзей с рисованными персонажами, анимационной сценой на диване, событиями, библиотекой, галереей, чатом и общими делами клуба.

Актуальное объединённое обновление: [состав и настройка базы](docs/release-2026-10-24.md).

## Сайт и домен

- Сайт: https://dearfriends.ru (GitHub Pages из ветки `main`).
- GitHub: https://github.com/fzfj42nbym-ux/dearfriends
- Главная страница: `index.html`.
- Сборка не требуется: обычные HTML, CSS и JavaScript.
- Локальный запуск (Windows, без установок):
  `powershell -NoProfile -ExecutionPolicy Bypass -File serve.ps1` → http://127.0.0.1:8642

## Публикация

1. Откройте **Settings → Pages** этого репозитория.
2. В **Build and deployment** выберите **Deploy from a branch**, ветку `main` и папку `/ (root)`. Нажмите **Save**.
3. В **Custom domain** укажите `dearfriends.ru` и сохраните, если не подставился автоматически из `CNAME`.
4. У регистратора домена настройте для корня (`@`) четыре A-записи GitHub Pages:

   - `185.199.108.153`
   - `185.199.109.153`
   - `185.199.110.153`
   - `185.199.111.153`

   Для `www` по желанию CNAME → `fzfj42nbym-ux.github.io`.

5. После выпуска сертификата включите **Enforce HTTPS** в настройках Pages.

Не удаляйте DNS-записи, относящиеся к почте (MX, SPF, DKIM), если почта на домене используется.

## Сверка с версией в ChatGPT

В репозиторий загружен исходный HTML-снимок `friends-club.html` (в нём подпись `v0.1`). В опубликованном ChatGPT Site встречается версия `v0.2` с персонажем «Коля “Усики”». Её редактируемый исходный код пока не был доступен для экспорта. Поэтому внешний сайт может отличаться от самой новой внутренней версии. Для полного переноса требуется получить и сравнить исходник `v0.2`; не выдумывать детали иллюстраций.

## Приватный клуб: Supabase (вход и общие данные)

Сайт подключается к Supabase — бесплатному сервису, который даёт авторизацию,
общую базу, хранилище фото и живой чат. Настройка по шагам:

1. **Проект создан**: `https://dlvjdnligiizwnpibwin.supabase.co`.
2. **Создать таблицы**: в Supabase откройте **SQL Editor → New query**,
   вставьте целиком файл [`supabase/schema.sql`](supabase/schema.sql) и нажмите **Run**.
   Повторный запуск безопасен.
3. **Пригласить друзей**: в конце `schema.sql` замените строку-пример и выполните:
   ```sql
   insert into public.members (email, name) values ('drug@pocta.ru', 'Настоящее имя');
   ```
   Человек сможет войти только с почты из этого списка (вход по ссылке из письма,
   без пароля). Имя из `members` показывается в чате.
4. **Вставить ключ**: в Supabase **Settings → API** скопируйте `anon public` key
   и вставьте его в `index.html` вместо `PASTE_ANON_KEY_HERE` (константа `SB_KEY`).
   Это публичный ключ — его можно коммитить. **`service_role` key никогда не
   коммитьте и никому не пересылайте.**
5. **Ссылки для входа**: в Supabase **Authentication → URL Configuration** добавьте
   в **Redirect URLs**: `https://dearfriends.ru` и `https://dlvjdnligiizwnpibwin.supabase.co/auth/v1/callback` (для локальной проверки — `http://localhost:8000` и т.п.).
6. **Письма со ссылкой**: встроенная почта Supabase шлёт ~2 письма в час — для
   теста хватает. Для клуба настройте свой SMTP в **Authentication → SMTP**.

Пока `SB_KEY` не вставлен, сайт работает в демо-режиме: интерфейс доступен,
но данные не синхронизируются, фото не загружаются.

### Демо-вход без почты

На экране входа есть отдельная форма **«Демо без почты»**: введите `123`
и нажмите **«Войти в демо»**. Можно попробовать общий чат, стикеры, локальные
события, просьбы о помощи и отклики, а также библиотеку с примерами фильмов,
сериалов, книг и игр. В меню «Ещё» работают локальные формы фонда, чеков,
челленджей и дней рождения с явно подписанными пробными данными.
Данные демо видны только в текущей вкладке и исчезают после
перезагрузки. Кнопка **«выйти из демо»** возвращает к экрану входа.

Код открывает демо-интерфейс; настоящие переписки, фото и синхронизация клуба
по-прежнему доступны после входа участника через Supabase. Демо-вход
не создаёт пользователя Supabase и не отправляет письмо.

Для предпросмотра в чате можно собрать отдельный HTML без сетевых зависимостей:

```bash
python3 scripts/export_demo.py /tmp/dearfriends-demo.html
```

В этом файле вход по `123`, библиотека, чат, стикеры, события, помощь и четыре
новых раздела работают локально, в том числе во встроенном окне, где запрещена
нативная отправка HTML-форм.
Кнопки открывают окна разделов, сохраняя вход и данные демо
внутри `srcdoc`-предпросмотра; перехода на адрес внешней страницы нет.
Supabase и CDN не используются, форма входа по почте скрыта.
Изображения комнаты уже встроены в основной `index.html` как `data:` URL,
поэтому фон и стол доступны и в обычном предпросмотре
`srcdoc`, где нет каталога `assets/room`. Исходные WebP сохранены в этом каталоге.
После их изменения обновите встроенные копии командой
`python3 scripts/export_demo.py --refresh-room-assets`.
Ссылка на экспортированный файл сама по себе
не публикует сайт и не создаёт общедоступный адрес для телефона.
Обычный экспорт с путём назначения основной `index.html` не изменяет.

### Главная и окна разделов

Главная занимает один экран: исходная иллюстрация с диваном, большая доска
ближайших анонсов, четыре рекомендации месяца и заметная доска **«Помощь и сборы»**.
Срочные обращения показаны первыми. На странице нет общей вертикальной прокрутки;
длинные списки прокручиваются внутри досок и окон. Горизонтальная прокрутка
длинного дивана на телефоне сохранена, как и все 17 персонажей и темы оформления.

По выбранному варианту № 3 добавлено оформление **«Комната»**: фон клуба,
отдельный передний план со столом и раздельные книжная и кинополка.
На широком экране предметы комнаты открывают существующие разделы:
фотографии — галерею, ноутбук — чат, надписи «Книги» и «Кино» — соответствующие
полки библиотеки. Четыре рекомендации месяца остаются связаны с данными,
а на полках нарисованы книги, диски с фильмами, коробки настолок и сувениры
из сериалов. Квадратные изображения поверх полок убраны; живые названия
рекомендаций остаются кнопками. Заголовки, значки и действия анонсов и помощи
помещаются внутри бумажных листов доски.
Доски анонсов и помощи остаются на главной. На телефоне используются панорама
и компактные карточки. «Комната» выбрана по умолчанию; сохранённый выбор темы,
а также «Неон», «Ретро» и «Минимал» сохранены.

Основная страница остаётся иллюстрированной комнатой с исходными SVG-героями.
Дальнейшая работа над отдельной 3D-основой отложена по просьбе владельца. [Слои, происхождение изображений и обновление оформления](docs/interactive-room.md).

**Чат, библиотека, галерея, события и помощь** открываются отдельно в
`#sectionWindow`, по примеру Бестиария. Закрытие возвращает на главную;
при повторном открытии сохраняются черновики, фильтры и состояние библиотеки,
поскольку содержимое раздела не создаётся заново. Можно закрыть окно кнопкой
или нажатием на фон; фокус возвращается к открывшей его кнопке. Escape сначала
закрывает вложенную карточку или просмотр фото, затем окно раздела.

На экранах до 800 px пять основных разделов доступны из нижней панели
**Чат, Полка, Фото, События, Помощь**; при открытом окне панель скрывается.
Бестиарий доступен отдельной кнопкой с лапой. На большом экране те же ссылки
остаются в шапке. В обычном браузере работают адреса `#chat`, `#library` и история
переходов; в `srcdoc` окна открываются без навигации внешней страницы.

Меню **«Ещё»** собирает семь окон: **Челленджи, Виш-листы, Дни рождения,
Общий фонд, Мастерская стикеров, Чеки и Комната клуба**. Фонд, чеки, дни рождения
и челленджи перенесены из прежнего GitHub `main` в новый интерфейс.
Заглушками **«Раздел готовим»** остаются виш-листы и мастерская стикеров;
комната клуба открывает отдельный процедурный 3D-прототип.
[Источники переноса, состояние и проверки](docs/club-features-sync.md).

Рекомендация месяца выбирается отдельно для книги, фильма, сериала и игры
из карточек со средней оценкой друзей от 4. Порядок определяется сглаженным
рейтингом `(сумма оценок + 7) / (число оценок + 2)`; месяц используется только
для выбора при равных баллах. Собственная оценка, поиск и личные фильтры полки
на подборку не влияют. Новые оценки могут изменить выбор в течение месяца;
это не отдельная редакционная подборка и не новая таблица в базе.
На карточке показаны настоящее среднее и число оценок друзей.

Доски используют уже загруженные события, обращения и библиотеку. При загрузке,
ошибке или отсутствии подходящей рекомендации показано соответствующее состояние.
Примеры библиотеки и вымышленные оценки в демо подписаны; настоящие данные клуба
не подставляются в демо. Просьбы о помощи и отклики в демо хранятся до перезагрузки.

Проверки окон, главной и навигации используют локальный браузер и изолированные данные:

```bash
python3 -B -m unittest discover -s tests -p 'test_navigation.py' -v
```

В автоматических проверках клавиатура моделируется изменением высоты окна;
поведение настоящей iOS/Android-клавиатуры требует проверки на устройстве.
Перестройка главной и навигации новых таблиц не требует. Общая библиотека
и серверные ограничения остальных разделов требуют актуального
`supabase/schema.sql`; отправка кода на GitHub не применяет SQL к рабочей базе.

### Фонд, чеки, челленджи и дни рождения

Через «Ещё» открываются четыре действующих окна:

- **Общий фонд** — взносы с комментарием, общая сумма, число взносов и участников,
  история и удаление своей записи.
- **Чеки** — сумма, описание и фото покупки, история и распределение общей суммы
  между участниками. Расчёты выполняются в копейках, включая остаток при делении.
- **Челленджи** — создание вызова с дедлайном, участие и выход, число участников,
  удаление своего вызова.
- **Дни рождения** — собственная дата, ближайшие праздники и поздравление в сам день.

Старые адреса `#rc`, `#chal` и `#bday` открывают соответствующие новые окна.
В демо формы работают с данными вкладки; при обычном входе — с таблицами Supabase.
Успешные действия обновляют список без ожидания realtime, ошибки сохраняют черновик.
Фонд ведёт учёт взносов: переводов денег, расходования кассы и автоматической связи
с чеками нет. Поздравительный баннер не отправляет сообщения участникам.

Для общей версии нужен актуальный `supabase/schema.sql`: таблицы совместимы
с версией GitHub и сохраняют существующие записи. Рабочая база и публикация этим
переносом не обновлялись. [Состав переноса, проверок и порядок обновления](docs/club-features-sync.md).

Проверка переноса завершена: прошли 74 браузерные и 57 серверных проверок.
В локальном Chromium просмотрены окна, формы и списки на телефоне и большом экране;
отдельно проверены добавление взноса, фото чека и просмотр изображения.

### Библиотека

В меню, заголовках разделов, полках, формах, состояниях и кнопках используются общие
контурные SVG-иконки. Они встроены в `index.html`, работают без сети и наследуют
цвет текущей темы; внешних библиотек и иконочных шрифтов нет. Подписи разделов
сохранены, декоративные SVG скрыты от скринридеров. На телефоне пять кнопок
полок образуют компактный ряд с иконкой и подписью. Векторные символы определены
в блоке `dfi-*`, динамические иконки добавляет `uiIcon()`. Кнопки загрузки фото,
событий, помощи, входа, сохранения оценок и выдачи книг используют те же ключи.
Фотографии открываются также с клавиатуры; у просмотра есть кнопка закрытия,
Escape и возврат фокуса к фотографии.

Для будущего приложения подготовлены **41 отдельный SVG**, общий спрайт,
`manifest.json` со стабильными ключами и автономный [каталог](assets/icons/preview.html).
Их можно пересобрать без зависимостей:

```bash
python3 -B scripts/export_icons.py --zip /tmp/dearfriends-icons-kit.zip
```

Источник рисунков остаётся один — inline SVG в `index.html`. Экспортированные
файлы находятся в `assets/icons`; [правила обновления и использования в приложении](docs/icons.md).
Нативное приложение этим изменением не создаётся.

Раздел **«Библиотека → Передай дальше»** — четыре отдельные полки: **Фильмы, Сериалы, Книги и Игры**. Они видны сразу над каталогом; по умолчанию открыты фильмы, кнопка «Всё» собирает библиотеку вместе:

- Добавление названия, автора, жанра и короткого описания; у фильмов и игр — длительность, у сериалов — минуты на одну серию, у игр — число игроков. Новая карточка открывается в своей полке; форма по умолчанию выбирает текущую полку.
- Поиск по названию, автору и жанру; фильтр категории, свой список и сортировка по среднему рейтингу или дате добавления.
- Оценка от 1 до 5, статус «хочу / в процессе / готово» и короткий отзыв. У каждого участника одна изменяемая оценка на карточку; среднее и число оценок видны всем друзьям. Оценку и статус можно очистить в карточке.
- **«Друзья советуют»** учитывает выбранную полку, поиск и личный список и показывает до трёх незавершённых карточек со средней оценкой друзей от 4. Собственная оценка не входит в этот блок. Для порядка используем сглаженный балл `(сумма оценок + 7) / (число оценок + 2)` и небольшой бонус 0,25 за жанр, которому ты уже ставил 4–5. На карточках показываем настоящее среднее и число голосов, чтобы было понятно основание совета; ИИ и внешних API нет.
- **«Выбрать на вечер»** случайно открывает одну карточку из текущей отфильтрованной подборки, исключая своё завершённое.
- Если у добавляющего есть экземпляр книги или игры, он отмечает это в форме. **«Взять почитать / поиграть»** записывает экземпляр на текущего участника. Вернуть его может получатель или добавивший карточку владелец. Физическую передачу друзья согласуют сами; учитывается один экземпляр на карточку, истории выдач пока нет.

В демо — восемь примерных карточек (по две в каждой полке) и оценки вымышленных друзей, явно подписанные над полкой. Можно добавлять карточки, оценивать, писать отзывы и проверять выдачу без подключения к сети. Всё хранится в памяти вкладки, до перезагрузки.

Для общего хранения повторно выполните актуальный [`supabase/schema.sql`](supabase/schema.sql) в SQL Editor своего Supabase-проекта: он добавляет `library_items`, `library_marks`, `library_loans` и функцию `borrow_library_item`. Если библиотека уже создана, повторный запуск обновит ограничения для категории `series`, сохранив существующие карточки, оценки и выдачи. Фильмы и сериалы не выдаются как физические экземпляры. Данные остаются доступны только действующим участникам через RLS. Клиент не может менять чужие оценки или напрямую записывать выдачи; сервер блокирует карточку при выдаче, исключая двойное получение. Каталог и отметки загружаются страницами, чтобы серверный лимит строк не обрезал рейтинг. Realtime обновляет полку, успешные действия также видны без ожидания события.

Миграция в рабочем Supabase **не выполнялась**. Без обновления схемы общая библиотека будет показывать ошибку загрузки с повторной попыткой; демо работает независимо.

Браузерные проверки и серверные проверки на отдельном PostgreSQL:

```bash
python3 -B -m unittest discover -s tests -p 'test_library.py' -v
python3 -B tests/check_library_sql.py
```

Условия запуска те же, что у проверок мессенджера ниже: локальные Playwright/Chromium и Docker, без обращения к рабочему Supabase. Проверяем также экспортированный HTML внутри `sandbox="allow-scripts"`, где нативная отправка форм запрещена.

Подборка следующих улучшений с первичными источниками: [тематические полки, ISBN-сканирование, обсуждения, итоги года и голосование на вечер](docs/library-research.md).

### Мессенджер

Раздел «Чат» — полноценный мессенджер клуба:

- **Все друзья** — общий чат (старая таблица `chat`).
- **Личные диалоги** — кнопка «＋ диалог», выбираешь друга из списка.
- **Группы** — «＋ группа», название и любой состав участников.
- **Изюминка**: у сообщений вместо ников — рисованные персонажи сайта, плюс
  эмодзи-реакции (наведи на сообщение). Реакции и переписки видны только
  участникам конкретного чата (RLS).
- **Поиск** над списком чатов фильтрует личные диалоги и группы по названию.
- **Ввод**: Enter отправляет сообщение, Shift+Enter добавляет строку.
  Черновик у каждого чата свой и хранится в памяти до перезагрузки страницы.
  При ошибке отправки текст остаётся в поле; повторная отправка доступна
  после завершения запроса. Отправленные сообщения появляются без ожидания realtime.
- Открываются последние 100 сообщений общего чата или 200 сообщений личной
  переписки в хронологическом порядке. Подгрузки более старой истории пока нет.
- Чтобы у друга в чате был персонаж, назначь его в Supabase:
  ```sql
  update public.members set char = 'kazar' where email = 'drug@pocta.ru';
  ```
  Доступные ключи персонажей: `kazar, alice, misha, diana, artemiy, marina,
  khariton, natasha, yulia, nikita, lena, kira, dima, sasha, vitya, vova, jenya`.

#### Обновление существующего Supabase-проекта

Перед публикацией этой версии повторно выполните `supabase/schema.sql`
в SQL Editor своего проекта. Скрипт сохраняет существующие данные и добавляет
функцию `create_conversation`: сервер проверяет участников и создаёт переписку
с её составом одной транзакцией. Приватность чтения сохраняется, прямое
добавление переписок и участников клиентом закрывается. Обновление схемы и
публикацию новой страницы выполняйте вместе: старый клиент использует прямые
вставки, новый — эту функцию. Без обновления схемы создание диалогов и групп
в новой странице работать не будет.

#### Проверки мессенджера

Браузерные регрессии запускаются из корня репозитория:

```bash
python3 -B -m unittest discover -s tests -p 'test_messenger.py' -v
```

Нужны Python Playwright и Chromium (`/usr/bin/chromium`), доступные в облачной
среде. Проверки используют локальный сервер и тестовый backend, внешние
запросы блокируются. Письма и сообщения реальным участникам не отправляются.

Проверка серверных правил на отдельном PostgreSQL требует локального Docker:

```bash
python3 -B tests/check_messenger_sql.py
```

Она создаёт временный контейнер без сети и открытых портов и удаляет его
после проверки. Рабочий Supabase-проект не используется.

### Как защищены данные

- Всё закрыто правилами RLS на стороне сервера: читать и писать могут только
  вошедшие пользователи из белого списка `members`.
- Фото лежат в приватном бакете `photos`; в галерее выдаются временные
  подписанные ссылки (на час).
- Паролей нет — вход по одноразовой ссылке на почту.

Репозиторий и сам сайт остаются публичными (это нормально: код не содержит секретов),
но все данные участников — события, чат, фото, просьбы — видны только членам клуба.
